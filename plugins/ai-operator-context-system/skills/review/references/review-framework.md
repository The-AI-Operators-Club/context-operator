# Review framework

Use this as a checklist for consequential or multi-criterion reviews, not as a mandatory output form.

| Check | Question | Evidence boundary |
| --- | --- | --- |
| Requirement coverage | Does each stated criterion have a supported Pass, Partial, Fail, or Cannot verify result? | Do not replace the actual standard with a preferred one. |
| Correctness | Can a factual, logical, technical, structural, or computational error be established? | Name the contradictory evidence or reproducible check. |
| Constraint adherence | Did the result cross a hard boundary? | Keep a chosen approach (Decision) distinct from a hard limit (Constraint). |
| Unsupported assumptions | Did it turn unknown state, inference, or a Hypothesis into fact? | Unsupported is not synonymous with false. |
| Completeness | Is required or materially necessary content absent? | A partial implementation is not a full Pass. |
| Consistency | Does the result contradict itself or relevant current state? | Do not enforce obsolete context. |
| Evidence | Does a consequential claim have the requested or necessary support? | Mark external claims Cannot verify when sources are unavailable. |
| Usability and failure risk | Can the intended recipient use it, and where would it materially fail? | Keep risks grounded and proportional. |

Prefer a short list grouped by Blocking, Material, and Minor findings, followed by acceptance status. Use Missing Requirements, Unsupported Assumptions, Constraint Violations, and Unresolved / Cannot Verify as separate headings only when that improves scanning. Each finding should connect the result to its actual standard and an actionable correction. If the artifact satisfies the standard, a concise clean Pass is better than a long empty template.
